# 使用 Cloudflare 托管，以免费计划和免费额度为硬约束

状态：已接受。记录用户在架构讨论中确认的方向，不表示技术方案已经部署验证。

我们选择在 Cloudflare 托管个人助手，以减少自有服务器和运行环境的维护。首个入口是适配手机的独立网页，云端优先保存小型资料，能力通过工具逐步添加。用户明确要求零支出起步，因此不以付费套餐、预充值或购买模型订阅为运行前提。

考虑过自有服务器运行 Pi Durable、使用 workerd 自托管，以及云端与本地执行器协同。这些方案增加运维或协同复杂度，当前不采用，也不为它们提前实现部署适配层。

这一决定意味着放弃第一版的完整 Linux 执行环境，不配置需要付费计划的 Dynamic Workers 和 Containers。Cloudflare Computer 只考虑 Workspace 文件系统，不默认启用动态代码执行。SDK 或 npm 包开源，不代表其依赖的云服务免费。

免费额度可能限制可用性、模型选择和任务长度。达到额度时停止或显示明确失败，不自动升级或转向收费服务。若免费限制阻止关键需求，需要向用户提出新的取舍，而不是默默改变约束。

价格和能力依据见 [免费额度核查](../research/cloudflare-free-tier.md)。内部设计和可行性仍以 [架构草案](../design/architecture.md) 的验证结果为准。
