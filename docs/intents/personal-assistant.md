# Intent：可持续扩展的云端个人助手

状态：整理用户已确认的产品方向。首版行为和验收仍需评审对应 Spec。

## 想要的产品

做一个类似用户提到的 Grok bot / OpenAI dot 的个人助手，而不是为某一个实验场景写死的自动化脚本。这两个产品名称只表达产品形态，不作为已经调查过的功能对标。

助手应能保持必要的上下文，使用资料和工具完成任务。需要新能力时，由我们添加工具、MCP 或其他经过设计的能力。第一版不要求助手自行安装软件或修改自己的部署。

## 已确认的目标与约束

- **I1，个人助手**：底层支持持续扩展，邮件、ehall 和深入研究是后续可能添加的能力，不反过来限定整个产品架构。
- **I2，手机可用**：第一入口是适配手机的独立网页，不能依赖桌面上始终打开的 Pi 对话窗口。
- **I3，持续积累**：助手应逐步利用个人资料和用户纠正。持久化聊天记录不等于已经实现长期记忆，具体行为需要另行定义。
- **I4，可组合能力**：新功能通过明确的工具接口接入，并能组合使用。模型可以调用哪些能力由产品授予，而不是由检索内容决定。
- **I5，Cloudflare 与自部署都支持**：（2026-10-22 修改，原为“纯云端、Cloudflare 免费计划起步，不做自托管”）用户的话：“我预感未来我们会选择自己部署，而非用 cloudflare 部署（当然都要支持）”。Cloudflare 部署仍只用 Free 计划，不依赖付费套餐，因此没有 sandbox；自部署提供完整 sandbox。模型由用户自己提供，费用由用户的模型供应商结算。不主动设置用量配额，但必须有兜底限制，防止失控循环。见 [ADR-0004](../adr/0004-pi-durable-portable-core.md)。
- **I6，拥抱 Google 生态**：（2026-10-22：Google Drive 改为插件，见[路线图 3](../plans/roadmap-3.md) H10）用户文件存放在用户自己的 Google Drive。后续的日历、Tasks 等能力优先接入 Google 服务，共用一个 Google 授权。（2026-10-21 确认，见 [ADR-0002](../adr/0002-think-google-drive.md)）

## 已决定的事项

- 登录：Cloudflare Access + Google 登录，只允许预先指定的用户。
- 模型：用户在 `.env` 中提供兼容 Anthropic API 的端点。

## 不预先决定的事项

- 文件大小和单轮工具调用次数的具体数值。
- 哪些记忆可以自动保存，哪些需要用户确认。
- 首版之后优先做邮件、校园事务、研究循环，还是其他工作流。

## 与课程材料的关系

[实验 1](lab1.md) 提供个人资料、邮件、校园事务、手机联动和纠正积累的场景。[实验 2](lab2.md) 提供 effort、查证循环和评估的方向。

这些场景不全部进入首版。当后续加入邮件发送或 ehall 提交时，必须保留原始意图中的最终内容确认和避免重复执行要求。高 effort 不能绕过兜底限制。
