# Roadmap 5 backend implementation notes

Work proceeds on `feat/r5-backend`, without editing `packages/web` or the fixed `packages/protocol` contract. Each stage includes this log in its commit. No parent agent, other agents, or pushes are used.

## B0 — package structure (N1)

- Merged core and the Node host into `@gense/server`, under `platform/`, `agent/`, `events/`, `channels/`, and `plugins/`. Removed protocol/notes forwarding files and the Drive plugin entry.
- Split conversation behavior into trees, branches/send, events, subagents, schedules and webhooks. `UserSpace` assembles typed, bound operations and owns runtime state.
- Updated workspace scripts, Docker entry point/manifests, Makefile checks, and startup paths. `check:server` checks protocol and server types and runs all server tests; it excludes the web package. Test temporary files stay in repository-local `data/test-tmp`.
- Tests: `npm run check:server` passed: protocol/server type checks and all 40 tests, including Docker sandbox and crash/restart recovery; 0 skipped.
- Protocol problems: none for this stage.
- Deviations and reasons: the existing host tests revealed that independently opened servers shared the fixed Docker container name, so closing one could kill another's command (exit 137). Container names now include a stable hash of the files directory. This isolates concurrent tests and separate data directories without changing sandbox behavior. The original 256 MB sandbox test limit is preserved.

## B1 — plugin registry and tool catalog (N26)

- Added `definePlugin` and a declaration directory for every built-in plugin. Each owns availability checks, settings, extension, resource URIs and view tools. Removed the catalog's ID-specific availability branches and `callTool` name dispatch.
- Plugin messages contain complete tool descriptions, enabled state, resources and view-only flags. Persisted per-tool switches update the real Harness registry for the next resolution. View calls require the declared plugin and pass the same switches.
- Added persisted owner preferences, initial/live `prefs` messages, and a preferences prompt section. Added title/message search across branches and authenticated password rotation with current-password verification, fresh cookie and revocation of older sessions.
- Tests: `npm run check:server` passed, 43 tests, 0 skipped. New tests exercise real SQLite, conversation tool resolution, actual artifact files, preferences/search with the faux model, and password/session rotation.
- Protocol problems: none.
- Deviations and reasons: pi-durable's `search` export searches tool descriptions, not transcripts; conversation search therefore uses its public conversation/context API and orders matching trees by update time. This avoids depending on its private storage schema.

## B2 — Skills (N24, N25)

- Parse YAML front matter, including folded/multiline descriptions, license, compatibility, metadata and allowed-tools, against the [Agent Skills specification](https://agentskills.io/specification). Preserve the three Chinese built-in names; enforce standard installed names and matching folder names.
- Install one or more Skills from uploaded ZIPs or shallow HTTP(S) Git fetches with optional ref/path. Reject traversal, symlinks, special files, duplicate archive paths, excessive file counts and oversized content. Git runs on the host without credentials/global config/hooks or prompts; fetches have time and disk limits and scratch cleanup.
- Persist complete directory bytes and origin in SQLite and project enabled directories into `/data/skills`. Disabled Skills remain available through `skill.read`; enabling or restarting reconstructs their files. Added install/remove/read requests, complete file lists, license/origin, and `canInstall: true`.
- Tests: `npm run check:server` passed, 46 tests, 0 skipped. Added ZIP byte preservation, nested files, YAML parsing, restart/switch/remove, invalid-source rejection, and a real shallow Git HTTP fetch selecting an unmodified Skill. The Git fixture serves this repository read-only; temporary downloads stay under repository-local `data/` and are removed.
- Protocol problems: `SkillInfo` has no compatibility/metadata/allowed-tools fields; they are preserved in `SKILL.md` and in server metadata, accessible through `skill.read`, without changing the contract.
- Deviations and reasons: SQLite retains installed file bytes so disabled directories can be removed from model discovery and reconstructed reliably after restart, while read/remove continue to work. Git installation accepts credential-free HTTP(S) URLs; SSH/local-file transports are excluded to prevent ambient host credentials and out-of-tree access.

## B3 — MCP (N20–N23)

- Added the official `@modelcontextprotocol/sdk` Streamable HTTP client, pinned to 1.32.2. Runtime MCP declarations share built-in plugin switches, per-tool controls, catalog messages and next-turn Harness selection.
- Added add/update/remove/reconnect/auth requests, encrypted request headers and OAuth data, server status/reasons, paginated tools/list, tool-list notifications, health checks and exponential reconnection. Unavailable servers leave the next model resolution; recovered servers return automatically.
- Namespaced MCP tools; more than 20 tools use pi-durable `deferred` and the real `tool_search` extension. Model calls preserve text/image blocks and structured results; browser calls follow `ToolCallResult` and reject other servers' tools.
- Added declared `ui://` reads restricted to `text/html;profile=mcp-app`, including resource CSP/border metadata. Added OAuth discovery, dynamic client registration, PKCE, encrypted tokens/verifier, expiring single-use state, and `/api/mcp/callback`. See the [official client documentation](https://ts.sdk.modelcontextprotocol.io/client).
- Tests: `npm run check:server` passed, 48 tests, 0 skipped. Local HTTP protocol servers cover initialization, deferred search/model execution, resource MIME/CSP, tool isolation/switches, outage and automatic recovery, encrypted headers/restart, and real OAuth discovery/registration/token exchange with PKCE and callback replay rejection.
- Protocol problems: none blocking. OAuth requires `PUBLIC_URL` plus `TOKEN_ENCRYPTION_KEY`; the fixed requests expose no manual client-registration fields, so this implementation uses servers' dynamic registration support.
- Deviations and reasons: health checks use tools/list on the existing connection (and process list-change notifications), which also refreshes the catalog. SDK authentication and its default same-origin redirect policy are retained rather than implementing another OAuth stack.

## B4 — Trigger, gate, threads and outbox (N1, N4, N6)

- Added durable `triggers`, `threads` and `outbox` tables, admission records and source allowlists. Web sends use requestId as Trigger id; duplicate requests return the original submission. Persist prepared branch selection before input so retries of edits keep the selected branch.
- Schedules, webhooks and branch/subagent reports now persist in Triggers and render their `<event>` input from that record. Removed the independent events table. Pending inputs/events and channel run monitoring resume after reopen.
- Added Channel interface/host, encrypted channel settings, pairing codes (single use, ten minutes), allow/revoke controls, initial/live channels messages and recent Trigger queries. Channel conversations retain source metadata, thread mapping and channel-only persona; web followups do not generate channel deliveries.
- Final run state and final messages/files enter the outbox in one transaction. The sender persists receipts, deduplicates by stable id, retries with exponential backoff and resumes unsent rows at startup. In-progress renders bypass the outbox.
- Tests: `npm run check:server` passed, 51 tests, 0 skipped. New real SQLite/faux-model/HTTP tests cover rejected inputs without conversations, pairing/replay/revoke, duplicate admission, thread/source/persona, web-only followups, atomic final queueing, persisted retries/receipts and recovery of inputs stored before submission. All prior schedule, webhook, subagent and SIGKILL recovery scenarios pass.
- Protocol problems: the fixed contract still exports `EVENT_KIND = 'app.event'` and `EventData` for transcript cards, without a Trigger transcript kind. The server retains that presentation marker, backed exclusively by Trigger records; it does not write independent app event storage. Changing the marker requires a coordinated protocol/frontend change.
- Deviations and reasons: test client fixtures now prefix their short request IDs by tree, since the new contract makes Trigger IDs global while old fixtures reused `r1` across unrelated trees. The production requestId is used unchanged. No old database migration is provided, as specified for beta.

## B5 — Feishu / Lark and final documentation (N2–N9)

- Added the official `@larksuiteoapi/node-sdk` (pinned 1.76.0) WSClient/Client channel. Server-declared settings cover App ID, encrypted App Secret, Feishu/Lark, streaming, group history count and persona. HTTP requests have deadlines; connection/reconnection state and bot identity are reported in ChannelInfo. See the [official SDK](https://github.com/larksuite/node-sdk).
- Private pairing is single-use and expires after ten minutes; binding and its command Trigger commit together. Private chats keep one thread mapping. Groups require an actual mention of this bot, map thread/root messages consistently, and bring in quoted messages and bounded thread history. Rejected inputs do not download attachments or call the model.
- Added `/new`, `/stop`, `/model` (list/select), `/help`, durable command replies and command recovery. Owner web followups remain web-only. Source metadata and the complete model/tool transcript remain available to web watches.
- Stream partials come from `pi.live.generation.message`; a throttled card is updated about once a second, then finalized through outbox. Card identity is persisted for recovery, pending stream writes finish before final writes, and deterministic provider UUIDs plus stored receipts deduplicate final sends. Files are snapshotted when final output is enqueued so a later workspace edit cannot change the queued attachment.
- Download image/file/post-image resources into attachments; preserve image MIME by signature. Generated referenced files/images upload through the real SDK and return to the originating private chat or group topic. Declared rich tool views fall back to a summary plus a `PUBLIC_URL` conversation link. Long cards and files outside Feishu's sending limits use the webpage as fallback.
- Updated architecture, README, `.env.example` and the runtime Docker image (Git/CA support for host Skill installation). `PUBLIC_URL` and a stable `TOKEN_ENCRYPTION_KEY` are required before enabling Feishu and for interactive MCP OAuth.
- Tests: final `npm run check:server` passed: **57 tests, 0 failures, 0 skipped**, including Docker. Local Feishu HTTP plus actual protobuf WebSocket frames exercise N2–N9: pairing/expiry/rejection, streaming throttle and same-card final, duplicate deliveries, shared transcript/source, websocket reconnect, group mentions/thread/quoted history, commands/model selection/abort, attachment transfer, generated files/images and rich-view links. A child process is SIGKILLed after final queueing; reopening sends exactly one final and ignores redelivery. Also verified an installed Skill script runs through the real read-only Docker Skills mount.
- Final contract review: corrected MCP Apps view calls to accept a server's original tool name as well as the model namespace, with the same server/tool-switch checks. Error status text exposes transport categories/status only, preventing server error bodies from echoing credentials. Corrected password rotation/logout to close revoked live WebSockets and revalidate each incoming socket request; a real HTTP/WebSocket regression test covers old-cookie revocation and new-cookie admission.
- Protocol problems: the B2 metadata and B4 `app.event` presentation issues remain documented above; the fixed protocol was not edited. The web package's existing genui scripts still reference the removed `core` output path; the frontend owner must retarget or replace those scripts during integration. No web files were changed, and frontend build/type checks were intentionally excluded.
- Deviations and reasons: Feishu needs `PUBLIC_URL` before activation to make N9 links usable. Incoming attachments are bounded by the app's 20 MB upload limit; Feishu image/file API limits determine outbound fallback. Enabled Skill directories are materialized from persisted bytes, with scripts run through interpreters rather than relying on archive executable bits. The fixed event display marker is retained as described in B4. No live platform credentials or deployment were used; acceptance uses the requested local protocol servers.

B0–B5 are complete on `feat/r5-backend`, with one commit per stage. No agents were started and no commits were pushed. `packages/web` and `packages/protocol` have no changes relative to the starting commit.
