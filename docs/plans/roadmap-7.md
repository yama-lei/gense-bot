# 路线图 7：记忆与项目、分享与临时对话、DeepSeek App API、补齐“预览”功能

状态：2026-11-14 用户同意，待定问题 Q1–Q6 全部按“建议”一栏决定；开始实施。依据：[网页界面 Spec](../specs/web-ui.md) 的“预览功能”一节、[ADR-0006](../adr/0006-multi-user.md)、DeepSeek 2026-11-13 公告与 [Build a Chatbot 指南](https://api-docs.deepseek.com/guides/build_a_chatbot)。

## Intent（2026-11-14）

| 编号 | 用户的话 | 整理后的目标 |
| --- | --- | --- |
| I1 | “公开分享链接、临时对话” | 对话可以生成只读的公开链接，可撤销；可以开不进历史、不用也不写记忆的临时对话 |
| I2 | “DeepSeek 公告里的 App API 集成” | DeepSeek 作为一等的模型提供方：联网搜索、读链接、安全检查、自动标题由服务端直接完成；单独提供的 OCR / ASR / TTS 用在附件、听写、朗读上 |
| I3 | “记忆、项目的完整功能” | 两者都由服务器保存、跨设备、送达模型（网页和飞书都生效）；项目有自己的指令和资料文件 |
| I4 | “其他只有前端有、或者前端不完善、后端缺失的功能” | 去掉所有“预览”徽标：要么接上后端，要么明确留在浏览器里（只是界面偏好的那些） |

分工（沿用路线图 5 的约定）：后端交给 `hc` 启动的 codex，在单独的 clone 里按阶段开发；Claude 写 `packages/protocol`（契约）、`packages/web`、所有模型看到的文字（系统提示词各节、工具说明、内置 Skill），并评审合并。

不在本轮范围：邮箱验证码与找回密码、订阅与支付、“参考全部历史对话”式的记忆（只做显式记忆条目）、导入 DeepSeek 的对话历史（格式未公开，见待定问题 Q5）。

## 现状盘点（I4 的依据）

| 功能 | 现在 | 本轮 |

| 公开链接、临时对话 | 禁用的入口 | 阶段 B |

| 资料库 | 浏览器逐个扫描最近 30 个对话的工作区 | 阶段 D：服务器一次返回全部对话和项目的文件，分页 |

## 阶段

```text
A  记忆与项目        后端 codex；协议、提示词、页面 Claude      最大，先做
B  分享与临时对话    后端 codex；公开页、入口 Claude           和 A 的前端并行
```

每个阶段一个分支（`feat/r7-a-memory-projects` 等）。节奏同路线图 6：Claude 先提交该阶段的协议类型 → codex 按协议实现并用真实 SQLite / faux 模型测试 → Claude 写前端并在真实服务器上走查 → 合并。

## Spec

验收都用真实的 SQLite、文件和 faux 模型；DeepSeek 的部分另用真实 key 走一遍。

### A. 记忆与项目

| 编号 | 场景 | 验收 |
| --- | --- | --- |
| A1 | 记忆存在服务器 | 记忆条目的增删改、开关在另一台设备上立即可见；用户之间隔离 |
| A2 | 记忆送到模型 | 打开“参考记忆”时，启用的条目作为系统提示词的一节（网页和飞书都是）；关掉时这一节消失 |
| A3 | 模型记住和忘记 | 用户说“记住……”“别再……”“忘掉……”时，模型用 `memory` 工具新增、修改或删除条目；回答里出现“已记住”的小标记，点开可撤销 |
| A4 | 不乱记 | 工具说明写清楚只记长期有用、用户本人的事实和偏好；不记一次性任务、密码和密钥（敏感内容被拒并提示） |
| A5 | 上限 | 条目数和总长度有上限（暂定 200 条 / 送给模型的部分不超过约 2k token，超出时新的提示“记忆已满”）；不做向量检索 |
| A6 | 存入记忆 | 回答的“更多 → 存入记忆”在服务器上新增条目，来源标“对话”并链接回该对话 |
| A7 | 项目存在服务器 | 项目的名称、颜色、指令、所属对话跨设备同步；对话标题菜单“移到项目”立即生效 |
| A8 | 项目指令 | 项目里的每个对话（含已有对话的后续轮次、从项目里新开的分支）都以系统提示词一节带上项目指令；不再塞进首条消息 |
| A9 | 项目资料 | 项目可以上传文件（单个 ≤ 20 MB，总量有上限）；项目里的对话在沙箱 `/data/projects/<id>/` 只读看到它们，提示词里列出文件名 |
| A10 | 项目记忆（Q2） | 条目可以属于某个项目，只在该项目的对话里送到模型 |
| A11 | 删除 | 删除项目时询问“同时删除其中的对话”还是“移出项目”；删除记忆条目立即从下一轮提示词中消失 |

### B. 公开分享与临时对话

| 编号 | 场景 | 验收 |
| --- | --- | --- |
| B1 | 创建链接 | 分享对话框里“创建公开链接”→ 得到 `/s/<token>`；内容是**创建那一刻**当前分支的快照，之后的对话不会出现 |
| B2 | 公开页 | 未登录也能打开；只读显示问答、Markdown、代码、生成式界面（只显示，不能调用工具）、图片；不显示思考过程、工具参数、工作区文件和 MCP Apps（Q3） |
| B3 | 更新与撤销 | 对话框里“更新链接”换成最新快照（链接不变）；“停止分享”后该链接返回 404；设置 → 数据里列出全部公开链接 |
| B4 | 安全 | token 不可猜（≥ 128 bit）；页面 `noindex`；公开页不带任何会话 cookie 能用的接口；内容里的附件只暴露快照引用到的那几个 |
| B5 | 临时对话 | 首页和新对话的开关“临时对话”；临时对话不进侧栏、搜索、收件箱、资料库，不读也不写记忆，不能分享，不能移到项目 |
| B6 | 临时对话的寿命 | 离开或 24 小时后（以先到者为准）服务器删除它和它的工作区；页面顶部一直有提示 |

### C. DeepSeek App API

| 编号 | 场景 | 验收 |
| --- | --- | --- |
| C0 | 调研 | `docs/research/deepseek-app-api.md`：Messages / Responses 两条路在 pi-ai 里能否透传 `safety_check`、`title`、服务端工具，能否解析 `server_tool_use`、`web_search_tool_result`、`web_fetch_tool_result`、`citations`；文件解析、OCR、ASR、TTS 的接口和价格；结论是选哪条路 |
| C1 | 提供方类型 | admin 登记共享提供方、用户添加 BYOK 时都可以选“DeepSeek”（只填 key），模型列表自动带出 `deepseek-flash` 等 |
| C2 | 原生联网 | 选 DeepSeek 模型时，“联网搜索”开关改用 `deepseek_web_search`，回答里的引用照常显示为来源卡片（标题、站点图标、摘要）；思考模式下是“深度思考搜索” |
| C3 | 读链接 | 用户消息里有链接时由 `deepseek_read_url` 读取，步骤里显示“读了哪些页面” |
| C4 | 安全检查 | 共享的 DeepSeek 提供方默认开 `safety_check: high`（公告要求面向公众的应用必须打开）；`stop_reason: refusal` 时显示我们自己的拒答说明 |
| C5 | 标题 | DeepSeek 模型的首轮回答顺带返回标题，用作对话标题，不再另外调用模型 |
| C6 | 附件 | 不支持该文件类型的模型（PDF、Office、扫描件）收到附件时，服务器先用文件解析 / OCR 转成文本，步骤里显示“已解析” |
| C7 | 听写与朗读 | 服务器配置了 DeepSeek 时，听写用 ASR、朗读用 TTS；否则回退到浏览器 |
| C8 | 记账 | 服务端工具的次数（`web_search_requests`、`web_fetch_requests`）和 ASR / TTS / OCR 调用进用量表，后台和设置 → 用量都能看到 |

### D. 其余预览功能

| 编号 | 场景 | 验收 |
| --- | --- | --- |
| D1 | 反馈 | 👍 / 👎 存服务器；👎 可选理由（不准确、没按要求、太长……）和一句话；`/admin` 用量页按模型统计 |
| D2 | 追问建议 | 回答完成后生成 2–3 条与内容相关的追问（用该用户可用的最便宜模型，或 DeepSeek 时随回答一起），关掉开关就不生成 |
| D3 | 收件箱已读 | 已读状态存服务器，跨设备一致；侧栏未读数由服务器给出 |
| D4 | 资料库 | 一次请求返回该用户全部对话和项目的文件（分页、按类型、搜索），不再在浏览器里扫描 |
| D5 | 导出全部 | 设置 → 数据 → 导出：服务器生成 zip（每个对话一份 Markdown + 工作区文件 + 记忆和项目的 JSON），完成后可下载 |
| D6 | 用量 | 设置 → 用量显示自己的 token、按模型和按天的汇总（共享模型和自带模型分开） |
| D7 | 没有“预览”了 | 界面上不再出现 `PreviewBadge`；`lib/lab.ts` 只剩设备偏好；web-ui Spec 的“预览功能”一节删除 |

## Design（草案，codex 动手前 Claude 细化到协议类型）

### A. 记忆与项目

- 表在每个用户的 `space.sqlite`：`memories(id, text, source, treeId, projectId, enabled, createdAt, updatedAt)`、`projects(id, name, color, instructions, createdAt, updatedAt)`、`trees.projectId`。项目文件放 `users/<id>/files/projects/<projectId>/`，沙箱只读挂载。
- 提示词：两个新的 `section(...)`——`memory`（启用的条目，按更新时间，超限截断）和 `project`（名称、指令、文件清单）。它们按对话变化，放在系统提示词靠后，不打乱前面的缓存。
- 工具：内置插件 `memory`，一个工具 `memory`（`add` / `update` / `remove`），说明由 Claude 写；结果带条目 id，前端据此显示“已记住”并提供撤销。
- 协议：`memories`、`memory.{add,update,remove}`、`projects`、`project.{create,update,remove,move}`、`project.files.*`；首次登录时把浏览器里的 `gense.projects` / `gense.memories` 一次性导入（前端做，导入后清掉本地）。

### B. 分享与临时对话

- `app.sqlite` 的 `shares(token, userId, treeId, branchId, snapshot JSON, createdAt, updatedAt)`——放在全局库里，未登录的请求才能直接按 token 找到。快照是已经渲染所需的轮次数据（同前端的 `Turn` 模型）加上引用到的图片；不存活的引用。
- `GET /api/share/:token` 返回快照；网页的 `/s/:token` 是一个不连 WebSocket 的只读视图，复用 `TurnView` 的只读模式。
- 临时对话：`trees.ephemeral`、`expiresAt`；列表和搜索过滤掉；`memory` 一节和工具对它不加载；定时清理沿用现有的任务机制。

### C. DeepSeek

- 先做 C0 再定设计。倾向：新增提供方类型 `deepseek`，走 Messages（`/anthropic/v1/messages`）——指南里引用、搜索结果卡片、标题都是按这条路描述的，而且 pi-ai 的 anthropic 实现可能已经认识 `server_tool_use`。若 pi-ai 不能透传额外字段，就在我们这边包一层 API（和现在 `openAIResponsesApi` 的处理方式相同）。
- `web` 插件现在已经用 DeepSeek 的 `/v1/tools/search` 和 fetch；选 DeepSeek 模型时用原生工具，其他模型继续用插件，两者对前端都产出同样的“来源”数据。
- 听写 / 朗读：服务器提供 `/api/speech/{asr,tts}`，前端 `speech.ts` 先探测服务器能力。

### D. 其余

- 反馈、已读：`space.sqlite` 两张小表；反馈的统计汇到 `app.sqlite` 方便后台查询。
- 追问：回答完成后的一个后台任务，结果作为该轮的附加数据推给前端；失败就不显示。
- 导出：后台任务生成 zip 放进用户的 `files/exports/`，完成后进收件箱。

## 决定（2026-11-14，原“待定问题”，均按建议）

| 编号 | 问题 | 决定 |
| --- | --- | --- |
| Q1 | 模型可以不经确认就写记忆吗？ | 可以，但每次都在回答里显示“已记住”并可撤销（ChatGPT 的做法）；另给一个开关“只记我明确要求的” |
| Q2 | 记忆要不要分“全局 / 项目内”两层？ | 要，成本小（一列 `projectId`），符合 Claude Projects 的习惯 |
| Q3 | 公开页显示到什么程度？ | 只显示问答和生成式界面；思考、工具细节、文件都不公开 |
| Q4 | 分享是快照还是实时？ | 快照（ChatGPT / Claude 都是），可手动“更新链接” |
| Q5 | 要不要做“导入 DeepSeek 的历史对话”？ | 暂不做：官方只在演示前端里提到，格式没公开；C0 调研时顺便看演示仓库的导入代码再定 |
| Q6 | 安全检查对 BYOK 也强制吗？ | 共享提供方强制开；BYOK 默认开，用户可关 |
