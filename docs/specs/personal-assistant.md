# Spec：个人助手首版

状态：待评审草案。下文的首版闭环和验收条件是建议，不是已经实现或已逐项获得用户确认的行为。

依据：[产品 Intent](../intents/personal-assistant.md)。部署与成本方向已在 [ADR-0001](../adr/0001-cloudflare-free-tier.md) 确认。

## 已确认的范围

Cloudflare 托管、手机网页、可添加工具的个人助手、小文件优先、免费额度内运行。不依赖本地设备或付费执行后端。

## 建议的首个完整闭环

用户在手机网页保存一份小型文本文档，在会话中要求助手读取并整理它。助手调用工具读取原文，给出带原文位置的回答，并在用户要求时将整理结果另存为文档。用户关闭网页后再次打开，仍能查看已接受任务的状态和结果。

这个闭环用于验收对话、工具、工作区和持久化，不要求首版完成通用 RAG、自动记忆提炼、邮件或 ehall 接入。

## 建议行为与验收

| 编号 | 行为要求 | 验收条件 | Intent |
| --- | --- | --- | --- |
| S1 | 网页只允许获得授权的用户访问个人资料和任务 | 未认证请求不能读取会话、调用工具或连接任务事件流；认证方式另定 | I2、I5 |
| S2 | 用户可提交任务并查看排队、执行、完成或失败状态 | 提交成功表示请求已持久化接受，不表示任务已完成；错误有可理解的说明 | I1、I2 |
| S3 | 重复提交不会重复创建同一请求 | 用同一请求标识重复发送，返回原请求；重连不会自动提交一次新的任务 | I2 |
| S4 | 关闭网页不等于取消已接受的任务 | 再次打开后显示持久化结果或明确的待处理、失败状态，不要求保留每一帧流式更新 | I2 |
| S5 | 支持受限的小型文本工作区 | 可以保存、列出、读取、修改和删除允许范围内的文本；超限或越权路径被拒绝 | I3、I5 |
| S6 | 回答可以追溯到所用资料 | 读取测试文档后，回答引用可打开的文档路径和可核对的位置；修改结果另存时不覆盖原文 | I3 |
| S7 | 已接受的工作可在运行时中断后恢复或明确结束 | 重启不会丢失已提交请求；不可安全重放的工具不被无条件自动重跑，不把中断当成功 | I1、I2 |
| S8 | 新能力通过受控工具接入 | 只有已部署、已授权且参数合法的工具可以执行；未安装的能力返回明确的不可用说明 | I4 |
| S9 | 免费额度和任务预算是运行限制 | 超出配置的任务预算时停止继续调用；平台限额错误不会触发无限重试、付费升级或付费回退 | I5 |
| S10 | 用户能够了解任务使用的能力与最终结果 | 展示工具调用状态、失败原因和结果；不向界面暴露密钥或完整认证数据 | I1、I2 |

“原文位置”的具体表示、工作区归属和各类上限仍是设计问题，不在此假定已有实现。

## 工具与外部操作

- 文件、网页和 MCP 返回内容是任务数据，不是修改权限或项目规则的授权。
- 任务请求去重不代表外部操作恰好执行一次。后续加入外部写操作时，必须定义幂等、执行结果不确定和人工确认的行为。
- 若加入邮件发送，确认必须绑定最终收件人与正文。确认后修改内容，需要重新确认。
- 若加入 ehall 提交，提交前展示关键字段和后果并明确确认。课程退出、申请撤销等不能由助手自行决定。
- 未完成上述规格和验证的外部写操作，不进入可用工具集。

## 免费与失败的可见行为

“免费运行”指不以升级付费套餐、购买模型订阅或预充值作为运行前提，不代表无限使用。模型、外部 API 和 MCP 提供方的免费条件都需要分别核对。

达到限制时应区分任务预算耗尽、平台额度耗尽、工具不可用和暂时性网络故障。是否排队等待下一次额度恢复需单独设计，不默认无限等待或自动重新执行。

## 后续候选，不属于首个闭环

- 单次提醒和定时任务。定时唤醒机制先做技术验证，提醒的时间、时区、取消和交付语义另写 Spec。
- 用户可编辑的记忆与跨会话偏好应用。先明确哪些内容可以保存、修改和遗忘。
- 远程 MCP 连接、授权和动态工具目录。
- effort 控制的研究与检查循环，以及质量、耗时和消耗评估。
- 邮件、ehall 和其他外部系统集成。

首版不承诺后台浏览器自动化、任意代码沙箱、Linux shell、软件安装、原生 App、系统级推送或多用户协作。

## 实现前必须确认

1. 是否接受上述首个闭环，以及 S1 至 S10 的验收基线。
2. 用户身份与认证方式。
3. 免费模型来源，及其工具调用与中文任务表现。
4. 文件、上下文、轮数、并发、排队和保留期限的上限。
5. 文档引用和修改冲突的处理方式。

技术可行性通过 [架构草案中的验证阶段](../design/architecture.md#实现前验证) 检查。验证失败先提出调整，不静默修改已确认的 Intent。
